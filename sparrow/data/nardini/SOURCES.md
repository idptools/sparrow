# NARDINI+ / GIN reference data

This directory holds reference data used by `sparrow.nardini`. Almost all of it is redistributed unchanged from the GIN resource; the one exception is the corrected GIN centroids, which sparrow refit from the published ones (see below). If you use any of it you must cite the original work.

## Files

### `gin_centroids_human_v1.npz`

The 30 GIN cluster centroids: a 30 × 90 matrix in sparrow's canonical NARDINI+ feature order (36 patterning features followed by 54 compositional features). Obtained by k-means (k=30) on the NARDINI+ z-score vectors of human IDRs of length 100–300, with z-scores clipped to ±3.

Keys: `feature_names`, `clusters`, `centroids`, `format_version`, `metadata_json`.

### `gin_cluster_definitions_human_v1.csv`

Human-readable description of each cluster plus the number of human IDRs assigned to it (24,508 in total). Columns: `cluster`, `description`, `num_idrs`.

These two files are what `load_gin_reference("published")` loads.

### `gin_centroids_human_corrected_v1.npz` and `gin_cluster_definitions_human_corrected_v1.csv`

The published GIN clusters refit to NARDINI+ vectors computed with sparrow's patterning windows, in the same two formats as the published files. This is what `load_gin_reference()` loads by default. Unlike everything else here, these were generated by sparrow — but from the published data, and they keep its clusters, so cite the GIN resource for them too.

Why they exist: the published GIN vectors came from the `nardini` package (v1.1.1), which scores `n - b + 2` patterning windows — the `n - b + 1` complete windows of `b` residues plus one holding only the last `b - 1` residues, still divided by `b`. That extra window is an off-by-one. sparrow scores the complete windows only, as the NARDINI+ notebooks themselves do, so its vectors are slightly off the published ones and belong with centroids fit in the same space. (That the published vectors include the extra window is an empirical finding: they agree with an `n - b + 2` recomputation to within Monte Carlo noise, and not with `n - b + 1`.)

How they were made, by `devtools/scripts/build_corrected_gin_reference.py`:

1. The 24,508 human IDRs of the GIN repository (≥ 30 residues, no X/U/Z/J/B/O), scored with sparrow against the published human prior: 100,000 scrambles for the 4,529 IDRs of 100–300 residues that define the clusters, 10,000 for the rest, master seed 42.
2. k-means started from the published centroids and run to convergence (4 iterations) on the clipped 100–300 residue vectors. Starting from the published centroids keeps every cluster's identity, so the published numbers and descriptions carry over; a fresh clustering would not, because the k-means landscape here is flat (rerunning the published k-means call on the published vectors agrees with the published partition at an adjusted Rand index of only 0.37–0.51).
3. `num_idrs` recounted by assigning all 24,508 IDRs to the refit centroids.

The effect: no centroid moves by more than 0.12% of the published centroid spacing (squared distance 0.021 against 17.8). 47 of the 4,529 clustering IDRs (1.0%) and 679 of the 24,508 human IDRs (2.8%) change cluster relative to the published calls; the movers sat on a boundary to begin with (median published separation 0.31, against 5.0 for all IDRs). The full provenance is in the archive's `metadata_json`.

### `gin_composition_prior_<species>_v1.npz`

Published per-species compositional backgrounds — the mean and standard deviation of each of the 54 compositional features across that species' IDRome (IDRs ≥ 30 residues). Stored in sparrow's `NardiniBackground` archive format, so they load directly via `NardiniBackground.load()` or `load_reference_background(species)`.

Available species keys: `human`, `mouse`, `rat`, `xenopus`, `fly`, `zebrafish`, `yeast`, `worm`, `arabidopsis`.

`num_sequences` is stored as `-1` because the published tables do not report how many IDRs went into them; `NardiniBackground.num_sequences` therefore reads as `None` for these.

## Regenerating

```bash
python devtools/scripts/build_nardini_reference_data.py
```

That script re-downloads the published data from the canonical locations and **verifies that the feature ordering still matches** sparrow's `COMPOSITION_FEATURE_NAMES` and `patterning_feature_names('8')` before writing anything, so a silent upstream reordering cannot corrupt the bundled data.

```bash
python devtools/scripts/build_corrected_gin_reference.py PATH_TO_GIN_REPOSITORY --vectors vectors.npz
```

rebuilds the corrected centroids from a checkout of the GIN repository and the bundled published centroids. Computing the vectors takes about an hour on 14 cores; `--vectors` saves them for reuse.

## A note on `W Patch`

sparrow's compositional feature set has 54 entries and deliberately contains no `W Patch` feature, matching these published tables. This is not an oversight. The original GIN pipeline did compute a tryptophan patch feature — its mean and standard deviation across the whole human IDRome are both exactly `0.0` (see `general_data/sapiens_full_idrome_gte_30_compositional_mean.npy` in the source repository, which has 55 entries). Tryptophan patches simply do not occur, so the feature carries no information and was dropped. Adding it back would break compatibility with these centroids and priors.
